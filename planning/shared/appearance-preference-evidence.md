# Personal accent color — implementation evidence

Date: 2026-11-24. Baseline: `2a161c2` (`feat/portal-navigation-home`, PR #95) plus uncommitted working tree on local branch `feat/appearance-preference`. Scope: [handoff](appearance-preference-handoff.md). Not committed, not deployed; no staging or live data touched.

## Delivered

- **Persistence:** migration `2026_11_29_000001_add_account_appearance` adds `users.appearance varchar(16) NOT NULL DEFAULT 'burgundy'` with `users_appearance_check` (`burgundy`, `purple`). A constant default, so existing rows need no rewrite. SQLite (identity tests) gets the same column without the check. No new table or settings service.
- **Endpoint:** `GET|POST /account/appearance` (`Account\AppearanceController`) inside the existing `auth` + `verified` group, so the global suspension, closure and owner-MFA middleware apply unchanged. CSRF via the web stack; throttled `20,1`. Validation uses `Rule::enum(App\Enums\Appearance)`. The target is always the session account; submitted `id`/`user_id`/profile fields are ignored and only `appearance`/`updated_at` change. On PostgreSQL the write runs in `TenantContext` (actor only), taking the account's privacy access barrier like other account writes.
- **Shared value:** `HandleInertiaRequests` shares `appearance` from `Appearance::for($request)`: the account's normalized value, or Burgundy for guests, unknown values and the shared/public pages (`/join`, `/partnerships/accept`, `/onboarding*`, `/lead`, `/kits/*`). `app.blade.php` writes the same allowlisted value to `<html data-appearance>`, so the first paint is correct before hydration. `syncAppearance` (registered in `app.ts`) applies the prop from every Inertia server response (`router.on('success')`), including sign-out and account changes. It ignores responses that omit the prop (partial reloads) and history restores, so Back after a save cannot bring back the old accent. No browser storage is used.
- **Tokens:** new `resources/css/appearance.css` (unlayered) overrides one set of tokens under `:root[data-appearance='purple']`: `--wd-brand`, `--wd-brand-hover`, the new `--wd-brand-soft`/`--wd-brand-wash`/`--wd-brand-wash-strong`, the shadcn `--primary`, and Tailwind `--color-brand`/`--color-blush` (covers `text-brand`, `bg-brand`, `bg-blush`, `bg-primary`, `bg-primary/90`). Hardcoded accent values were replaced by tokens in `foundation.css` (account-menu highlight, link-pill hover, workspace initial), `portal-shell.css` (current item and Brand experience chip), `admin.css` (current admin nav), `toasts.css` (info toast) and `WorkspaceScreen.vue` (initial and type chip). The Inertia progress bar uses `var(--wd-brand)`. Burgundy values are unchanged, so the default renders as before.
- **UI:** `pages/AccountAppearance.vue` (FoundationShell, `wd-page-heading`, `ContentSection`, `ActionGroup`, shared `Button`) with a native radio group following the `WorkspaceCreateForm` card pattern: named swatches, a text “Current” marker and an ink outline for selection (not color alone), explicit Save, disabled fieldset while saving, inline `role="alert"` error and the existing flash toast for success. `AccountMenu` gains an **Appearance** item (hidden while the account is closing).
- **Privacy export:** the personal archive's `account.json` now includes `appearance`.

**Defect fixed during verification:** the shell's current-item tint was a variable declared on `.wd-portal`, which the teleported mobile drawer is outside, so the drawer's current item had no tint in either palette. Both uses now read the root `--wd-brand-soft`.

**Intentionally unchanged:** `BrandLogo` (logo asset), `wd-partner-avatar.is-blush` (categorical avatar tint), mail theme, media kit Blade, danger/warning/success/focus/stage/chart colors, Brand's white header (D23). No third theme, dark mode, workspace theme or polling.
