## Quality approach

Proposed tools for the approved stack: Pest/PHPUnit for Laravel unit/feature/policy tests and Inertia response assertions; Vitest with Vue Test Utils for Vue components; Playwright for browser journeys; real PostgreSQL/Redis for integration, RLS, queue, and scheduler tests. Use Laravel Pint, PHP static analysis (for example Larastan), TypeScript/vue-tsc, and frontend lint/format checks in CI when implementation starts. SQL assertions can run directly or via pgTAP if selected; never substitute SQLite or mocked RLS for tenant tests. Test web redirects/error bags and JSON contracts separately, and test shared/deferred Inertia props for data leakage. These tools are planning choices; no packages are installed.

No arbitrary line-coverage percentage is prescribed. Release gates focus on permissions, money, workflow transitions, idempotency, and failure recovery. Every new tenant table and query path needs an adversarial tenant test. Include private creator data, shared projections, public capabilities, files, exports, caches, workers, and admin/support paths.

CI progression: PHP/frontend style and static checks → Pest/PHPUnit and Vue component tests → PostgreSQL migration/RLS tests → web/Inertia and JSON integration tests → browser smoke tests → image build and vulnerability checks → controlled deployment → smoke test. Production rollout approval applies only when later requested; this phase creates planning documents only.
