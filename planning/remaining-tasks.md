# Remaining Tasks Across Milestones

Status: **active carry-forward register**, established 2026-10-23. The user requested preserving unfinished, in-progress and deferred work when advancing milestones. This register supplements the original contracts and evidence; it does not waive acceptance or turn proposals into approved scope. Start with the [current handoff](implementation-handoff.md) and [M6 readiness contract](m6-readiness-contract.md).

## Tracking rules

- Keep IDs stable. Update an existing row when work moves milestones; retain its origin and source links. Do not delete a task merely because a later milestone starts.
- Status values: **not started**, **in progress**, **decision needed**, **verification pending**, **deferred**, **complete**. Only mark complete with linked implementation/decision and actual acceptance evidence. Keep completed rows or move them to a linked archive.
- A development-complete milestone can still have open release gates. Historical test results apply to their recorded revision and scope. A missing current run is verification work, not proof that implemented features are absent.
- **Required** rows must close before their dependent live-data/pilot/commercial gate. **Conditional** rows apply only when that scope is chosen. **Deferred** rows remain discoverable without becoming M6 blockers. Record an explicit approved scope change if a required feature is deferred further.
- Before each handoff, reconcile this register with milestone status files, decisions, contracts and evidence. Include newly discovered gaps and retain unresolved assumptions. Superseded proposals, such as the old application stack, are not unfinished implementation tasks.
